# PolyBenchC 数据集程序用途详解

这份文档用于解释 `datasets/PolyBenchC-4.2.1` 中各个 benchmark 的用途、输入规模含义、输出含义和主导时间复杂度。它不是按“文件类型”理解数据集，而是按“一个 benchmark 程序”理解数据集。

PolyBenchC 的每个正式 benchmark 通常由同目录下的一对文件组成：

1. `xxx.c`：程序主体，包含 `main()`、数据初始化、核心计算 kernel、计时调用和结果输出保护。
2. `xxx.h`：该程序的规模参数和数据类型定义，例如 `N`、`M`、`NI`、`NJ`、`TSTEPS` 等。
3. `utilities/polybench.h`：公共宏和函数声明，例如数组分配、计时、输出保护等。
4. `utilities/polybench.c`：公共运行时实现，例如 `polybench_alloc_data`、计时器、cache flush 等。

默认情况下，PolyBenchC 的头文件会启用 `LARGE_DATASET`。也就是说，如果不额外指定 `MINI_DATASET`、`SMALL_DATASET`、`MEDIUM_DATASET` 或 `EXTRALARGE_DATASET`，程序会使用 LARGE 规模。下面列出的规模例子均按当前数据集默认 LARGE 规模说明。

复杂度说明中，通常只分析核心 kernel 的主导复杂度，不把数据初始化、结果打印、防止死代码消除的输出逻辑作为主导项。实际运行时间还会受到 cache 局部性、编译优化、数据类型、内存带宽、向量化和硬件环境影响。

PolyBenchC 的“输出”要特别理解：这些 benchmark 不是为了生成业务结果文件，而是为了让计算结果被使用，避免编译器把核心计算优化掉。很多程序通过 `print_array` 或 `polybench_prevent_dce` 把结果矩阵/向量作为 correctness sink。做运行时间预测时，真正关心的是“输入规模 + 程序结构 + 执行时间”，不是输出内容本身。

## 1. datamining：数据挖掘类

这一类程序模拟统计学习和数据分析中常见的矩阵统计运算。它们的输入通常是“样本 x 特征”的二维数据矩阵，核心负载是对大量数据做均值、方差、协方差或相关性计算。

1. `datamining/correlation/correlation.c`

   `correlation` 用于计算数据集中各个特征之间的相关系数矩阵。可以把输入理解为一个数据表：有 `N` 条样本，每条样本有 `M` 个特征。程序先对每个特征求均值和标准差，再把数据标准化，最后计算特征两两之间的相关系数。

   默认 LARGE 规模是 `M=1200, N=1400`。也就是说，可以理解为 1400 个样本、1200 个变量/特征，输出是一个 `M x M` 的相关系数矩阵。

   时间复杂度主要由特征两两相关性计算决定。求均值、标准差和标准化约为 `O(MN)`，相关矩阵计算约为 `O(M^2N)`，因此主导复杂度是 `O(M^2N)`。当 `M` 很大时，相关矩阵的双特征组合会明显主导运行时间。

   在性能建模中，它代表统计分析类任务，例如数据预处理、特征相关性分析、金融因子相关分析等。它既有大量浮点运算，也有连续矩阵扫描，适合观察数组访问、浮点运算和 cache 行为。

2. `datamining/covariance/covariance.c`

   `covariance` 用于计算协方差矩阵。它和 `correlation` 很像，也处理一个 `N x M` 的数据矩阵，但输出的是特征之间的协方差，而不是归一化后的相关系数。协方差常用于 PCA、统计建模、信号分析和机器学习预处理。

   默认 LARGE 规模同样是 `M=1200, N=1400`。输出是一个 `M x M` 的协方差矩阵。

   时间复杂度和 `correlation` 类似。均值计算约为 `O(MN)`，中心化数据约为 `O(MN)`，协方差矩阵计算约为 `O(M^2N)`，因此主导复杂度是 `O(M^2N)`。相比 `correlation`，它少了标准差归一化部分，但主导阶数相同。

   它适合用来观察“统计类矩阵规约 + 对称矩阵输出”的运行时间特征。

## 2. linear-algebra/kernels：线性代数核心计算

这一类程序不是完整应用，而是抽取出的线性代数核心 kernel。它们通常有清晰的数组维度和循环结构，很适合做 AST、CFG、LLVM IR 指标提取的基础实验。

3. `linear-algebra/kernels/2mm/2mm.c`

   `2mm` 表示 two matrix multiplications，即连续两次矩阵乘法。程序通常可以理解为先计算临时矩阵 `tmp = alpha * A * B`，再计算 `D = beta * D + tmp * C`。

   默认 LARGE 规模是 `NI=800, NJ=900, NK=1100, NL=1200`。大致对应 `A` 为 `NI x NK`，`B` 为 `NK x NJ`，`C` 为 `NJ x NL`，`D` 为 `NI x NL`。输出是更新后的矩阵 `D`。

   时间复杂度由两次矩阵乘法相加决定。第一次矩阵乘法约为 `O(NI * NJ * NK)`，第二次约为 `O(NI * NL * NJ)`，因此总体主导复杂度是 `O(NI*NJ*NK + NI*NJ*NL)`。初始化和缩放矩阵 `D` 的 `O(NI*NL)` 通常不是主导项。

   这个程序计算量很大，核心是三重循环矩阵乘法链。它适合代表高算术强度的 dense linear algebra，运行时间通常主要受浮点乘加和 cache 复用影响。

4. `linear-algebra/kernels/3mm/3mm.c`

   `3mm` 表示 three matrix multiplications，即连续三次矩阵乘法。典型形式是先算 `E = A * B`，再算 `F = C * D`，最后算 `G = E * F`。

   默认 LARGE 规模是 `NI=800, NJ=900, NK=1000, NL=1100, NM=1200`。它涉及更多矩阵和更多中间结果，输出通常是最终矩阵 `G`。

   时间复杂度由三次矩阵乘法共同决定，约为 `O(NI*NJ*NK + NJ*NL*NM + NI*NJ*NL)`。如果各维度数量级相近，可以粗略理解为三段 `O(N^3)` 计算的组合。

   与 `2mm` 相比，`3mm` 的计算链更长，中间矩阵更多，内存占用也更高。它适合测试模型能否区分“相似循环形态但计算链更复杂”的程序。

5. `linear-algebra/kernels/atax/atax.c`

   `atax` 计算类似 `y = A^T * (A * x)` 的操作。x是列向量，它先做一次矩阵向量乘，得到临时向量，再用矩阵转置继续乘向量。

   默认 LARGE 规模是 `M=1900, N=2100`。可以理解为矩阵 `A` 的大小约为 `M x N`，输入向量 `x` 的长度为 `N`，输出向量 `y` 的长度也与 `N` 相关。

   时间复杂度主要是两次矩阵向量乘。第一次 `A*x` 约为 `O(MN)`，第二次 `A^T*tmp` 约为 `O(MN)`，总体仍是 `O(MN)`。它不是三重循环矩阵乘法，而是二维矩阵扫描。

   这个程序相比矩阵乘法更偏内存带宽，因为矩阵向量乘的数据复用少于矩阵矩阵乘。它适合观察 load/store、数组下标访问和内存/算术比例特征。

6. `linear-algebra/kernels/bicg/bicg.c`

   `bicg` 是 BiCG 迭代法中的一个简化核心，通常同时计算 `q = A * p` 和 `s = A^T * r`。它来自迭代求解线性方程组的数值算法背景。

   默认 LARGE 规模是 `M=1900, N=2100`。输入包括矩阵 `A` 和向量 `p`、`r`，输出是向量 `q` 和 `s`。

   时间复杂度同样由两次矩阵向量方向的扫描决定，约为 `O(MN)`。虽然输出有两个向量，但核心仍是对 `A` 的二维遍历和乘加。

   它和 `atax` 类似，也是矩阵向量型 kernel，但有两个方向的乘法结果。性能上通常偏内存访问密集，适合研究矩阵扫描、转置访问和向量规约。

7. `linear-algebra/kernels/doitgen/doitgen.c`

   `doitgen` 是一个三维数组和矩阵相乘的 kernel。它可以理解为对三维数据 `A[NR][NQ][NP]` 的每个二维切片执行矩阵变换。

   默认 LARGE 规模是 `NR=150, NQ=140, NP=160`。输入主要是三维数组 `A` 和二维矩阵 `C4`，输出是更新后的三维数组 `A`。

   时间复杂度来自对每个 `(r,q,p)` 再遍历一个 `s` 维度的乘加，因此约为 `O(NR * NQ * NP^2)`。当 `NP` 增大时，复杂度以平方方式增长。

   这个程序比普通二维矩阵运算多了一层数据维度，循环结构中有三维数组访问和临时向量。它适合测试程序表示能否反映多维数组访问和较复杂的循环嵌套。

8. `linear-algebra/kernels/mvt/mvt.c`

   `mvt` 表示 matrix vector product and transpose，即同时做矩阵向量乘和转置矩阵向量乘。典型形式是更新 `x1 = x1 + A * y1` 和 `x2 = x2 + A^T * y2`。

   默认 LARGE 规模是 `N=2000`。输入是 `N x N` 矩阵和多个长度为 `N` 的向量，输出是更新后的向量 `x1` 和 `x2`。

   时间复杂度约为 `O(N^2)`。程序会对矩阵进行两种方向的遍历，但每种遍历仍是二维矩阵扫描，所以总体阶数是平方级。

   这个程序的算术强度不如 GEMM，高比例时间会花在读取矩阵元素上。它适合代表带宽敏感的线性代数任务。

## 3. linear-algebra/blas：BLAS 风格运算

BLAS: 基础线性代数子程序库。这一类程序对应 BLAS 中常见的矩阵/向量基本运算。它们非常适合性能建模，因为循环结构规整、理论复杂度清楚，并且能明显区分计算密集和内存密集任务。

9. `linear-algebra/blas/gemm/gemm.c`

   `gemm` 是通用矩阵乘法，通常形式为 `C = beta * C + alpha * A * B`。这是高性能计算中最经典的 dense matrix multiplication。

   默认 LARGE 规模是 `NI=1000, NJ=1100, NK=1200`。可以理解为 `A` 是 `NI x NK`，`B` 是 `NK x NJ`，`C` 是 `NI x NJ`。输出是更新后的矩阵 `C`。

   时间复杂度由矩阵乘法决定，约为 `O(NI * NJ * NK)`。如果三维规模接近，就可以粗略理解为 `O(N^3)`。矩阵 `C` 的缩放是 `O(NI*NJ)`，通常低于乘法主项。

   它是典型计算密集型程序，三重循环清晰，乘加操作数量巨大。对于本项目，`gemm` 是衡量 IR 算术指令、循环深度、load/store 比例与运行时间关系的代表样本。

10. `linear-algebra/blas/gemver/gemver.c`

   `gemver` 是矩阵向量运算和 rank-1 更新的组合。它会先用向量外积更新矩阵，再做若干矩阵向量乘和向量更新。

   默认 LARGE 规模是 `N=2000`。输入包括一个 `N x N` 矩阵和多个长度为 `N` 的向量，输出通常是更新后的向量 `w`。

   时间复杂度约为 `O(N^2)`。rank-1 矩阵更新是 `O(N^2)`，后续矩阵向量乘也是 `O(N^2)`，若干向量加法只是 `O(N)`。

   这个程序比单纯矩阵向量乘更复杂，既有矩阵更新，又有向量规约。它适合代表“混合型 BLAS kernel”：既有较多访存，也有一定计算量。

11. `linear-algebra/blas/gesummv/gesummv.c`

   `gesummv` 是两个矩阵向量乘的加权求和，形式类似 `y = alpha * A * x + beta * B * x`。

   默认 LARGE 规模是 `N=1300`。输入是两个 `N x N` 矩阵 `A`、`B` 和向量 `x`，输出是向量 `y`。

   时间复杂度约为 `O(N^2)`。它需要扫描两个矩阵，但仍然是矩阵向量乘，不是矩阵矩阵乘。

   它的结构比 `gemm` 简单很多，但会连续扫描两个矩阵。性能通常偏内存带宽，适合与 `gemm` 对比：两者都有矩阵访问，但计算/访存比差异很大。

12. `linear-algebra/blas/symm/symm.c`

   `symm` 是 symmetric matrix multiply，即对称矩阵乘法。它利用一个矩阵的对称性质来更新结果矩阵。

   默认 LARGE 规模是 `M=1000, N=1200`。输入包括对称矩阵 `A`、矩阵 `B` 和结果矩阵 `C`，输出是更新后的 `C`。

   时间复杂度大致为 `O(M^2 * N)`。原因是外层通常遍历 `M x N` 的结果区域，同时内层只遍历对称矩阵的一部分，平均仍是与 `M` 成正比的三角区域访问。

   它的访问模式比普通 GEMM 更特殊，因为只需要使用对称矩阵的一部分或以对称方式访问。适合观察分支边界、三角区域访问、数据复用对性能的影响。

13. `linear-algebra/blas/syr2k/syr2k.c`

   `syr2k` 是 symmetric rank-2k update。它用两个矩阵 `A`、`B` 对对称矩阵 `C` 做更新，形式类似 `C = beta*C + alpha*A*B^T + alpha*B*A^T`。

   默认 LARGE 规模是 `M=1000, N=1200`。输出是更新后的对称矩阵 `C`。

   时间复杂度约为 `O(N^2 * M)`。输出矩阵 `C` 是按 `N x N` 的对称区域更新，每个元素需要沿 `M` 维度做乘加；rank-2k 相比 rank-k 常数更大，但阶数相同。

   相比 `syrk`，`syr2k` 多了一个矩阵和一组对称更新，计算量更高，数据访问也更复杂。它适合测试模型能否区分 rank-k 和 rank-2k 这类相近 kernel。

14. `linear-algebra/blas/syrk/syrk.c`

   `syrk` 是 symmetric rank-k update，典型形式为 `C = beta*C + alpha*A*A^T`。

   默认 LARGE 规模是 `M=1000, N=1200`。输入主要是矩阵 `A` 和对称矩阵 `C`，输出是更新后的 `C`。

   时间复杂度约为 `O(N^2 * M)`。虽然只更新对称矩阵的一半区域，但大 O 记号下仍按 `N^2` 级别看，内层沿 `M` 维度累加。

   它是矩阵乘法的一个特殊形式，计算密集，但只更新对称结果的一部分。适合分析循环边界、下三角/上三角区域访问和浮点运算密度。

15. `linear-algebra/blas/trmm/trmm.c`

   `trmm` 是 triangular matrix multiply，即三角矩阵乘法。它用一个三角矩阵乘以普通矩阵。

   默认 LARGE 规模是 `M=1000, N=1200`。输入包括三角矩阵 `A`、矩阵 `B`，输出是更新后的 `B`。

   时间复杂度约为 `O(M^2 * N)`。三角矩阵让内层遍历平均只有完整矩阵的一半，但阶数仍然是平方乘以另一维。

   因为三角矩阵只在一半区域有有效数据，所以循环边界通常不是完整矩形。它适合观察不规则但仍结构化的循环边界，以及这类边界如何影响 CFG 和分支指标。

## 4. linear-algebra/solvers：线性方程求解器核心

这一类程序模拟数值线性代数中的分解和求解过程。与 BLAS kernel 相比，它们通常有更强的数据依赖，某些循环难以并行，运行时间不仅受计算量影响，也受依赖链影响。

16. `linear-algebra/solvers/cholesky/cholesky.c`

   `cholesky` 是 Cholesky 分解，用于把对称正定矩阵分解为三角矩阵形式。它常用于求解线性方程组、最小二乘、协方差矩阵处理等场景。

   默认 LARGE 规模是 `N=2000`。输入是 `N x N` 矩阵，输出是分解后的矩阵。

   时间复杂度约为 `O(N^3)`。虽然只处理三角区域且常数小于通用矩阵乘法，但主导部分仍来自嵌套循环中的矩阵更新。

   这个程序有明显的三角区域访问和数据依赖。与 `gemm` 的规整三重循环不同，Cholesky 的后续计算依赖前面已经分解出的结果，因此适合分析依赖型数值算法。

17. `linear-algebra/solvers/durbin/durbin.c`

   `durbin` 是 Durbin 算法，用于求解 Toeplitz 系统。Toeplitz 矩阵具有沿对角线元素相同的特殊结构，在信号处理和时间序列分析中常见。

   默认 LARGE 规模是 `N=2000`。输入通常是一个长度为 `N` 的向量，输出是求解得到的向量 `y`。

   时间复杂度约为 `O(N^2)`。外层递推推进问题规模，内层会回扫已有向量，因此总体是平方级。它的空间结构是向量级，但时间并不是线性的。

   它不像 GEMM 那样有巨大的矩阵乘法，而是有递推式依赖。运行时间受循环递推和数据依赖影响，适合代表“向量递推型 solver”。

18. `linear-algebra/solvers/gramschmidt/gramschmidt.c`

   `gramschmidt` 是 Gram-Schmidt 正交化，用于把一组向量转换为正交基。它常用于 QR 分解、最小二乘和数值线性代数。

   默认 LARGE 规模是 `M=1000, N=1200`。输入是 `M x N` 矩阵 `A`，输出通常是正交矩阵 `Q` 和上三角矩阵 `R`。

   时间复杂度约为 `O(M * N^2)`。原因是需要对列向量之间做点积、投影和更新，通常有两层列循环和一层长度为 `M` 的向量循环。

   这个程序包含点积、归一化、向量更新等操作。它既有计算密集部分，也有规约和数据依赖，是一个很好的混合型 solver benchmark。

19. `linear-algebra/solvers/lu/lu.c`

   `lu` 是 LU 分解，把矩阵分解为下三角矩阵和上三角矩阵。它是求解线性方程组的经典方法。

   默认 LARGE 规模是 `N=2000`。输入是 `N x N` 矩阵，输出是原地存储的 LU 分解结果。

   时间复杂度约为 `O(N^3)`。主导部分来自分解过程中对剩余子矩阵的三重循环更新。

   LU 分解有三重循环，但循环之间存在前后依赖。它适合与 `gemm` 对比：两者都有大量浮点运算，但 LU 的控制和依赖结构更复杂。

20. `linear-algebra/solvers/ludcmp/ludcmp.c`

   `ludcmp` 是 LU decomposition and solve。它不仅做 LU 分解，还继续执行前代/回代来求解线性系统。

   默认 LARGE 规模是 `N=2000`。输入包括矩阵 `A`、向量 `b` 等，输出是解向量 `x`。

   时间复杂度主导项仍是 LU 分解的 `O(N^3)`。后续前代和回代通常是 `O(N^2)`，低于分解主项。因此整体复杂度可记为 `O(N^3)`。

   相比 `lu`，`ludcmp` 更接近完整求解流程，包含分解和求解两个阶段。它适合代表更完整的数值求解器工作负载。

21. `linear-algebra/solvers/trisolv/trisolv.c`

   `trisolv` 是 triangular solver，即三角线性系统求解。它通常执行回代过程，用三角矩阵求解向量。

   默认 LARGE 规模是 `N=2000`。输入是三角矩阵和右端向量，输出是解向量。

   时间复杂度约为 `O(N^2)`。每一行求解需要累加已经求出的若干变量，所有行累加起来形成三角区域遍历。

   这个程序的计算量不如矩阵乘法巨大，但数据依赖非常强。每一步求解都依赖前面求出的结果，因此适合观察串行依赖对运行时间的影响。

## 5. medley：混合类程序

`medley` 目录包含一些不完全属于普通线性代数或 stencil 的程序。它们更接近特定领域算法，例如图算法、图像处理、生物信息学动态规划。

22. `medley/deriche/deriche.c`

   `deriche` 是 Deriche 图像滤波算法，用于图像边缘检测或平滑处理。它通过递归滤波的形式对二维图像做处理。

   默认 LARGE 规模是 `W=4096, H=2160`，可以理解为一张接近 4K 分辨率的图像。输入是二维图像数组，输出是滤波后的图像。

   时间复杂度约为 `O(W * H)`。它会对图像做若干次行扫描和列扫描，扫描次数是常数级，因此总体随像素数量线性增长。

   它不是普通矩阵乘法，而是图像处理中的行列扫描和递推滤波。适合代表图像处理任务，运行时间通常受内存带宽、cache 局部性和递推依赖影响。

23. `medley/floyd-warshall/floyd-warshall.c`

   `floyd-warshall` 是 Floyd-Warshall 全源最短路径算法。它用于计算图中任意两个节点之间的最短距离。

   默认 LARGE 规模是 `N=2800`。输入可以理解为一个 `N x N` 的距离矩阵，输出是更新后的最短路径距离矩阵。

   时间复杂度是典型的 `O(N^3)`。三重循环分别对应中间点、起点和终点，所有节点对都会在每个中间点下被检查一次。

   它的结构非常规整，但数据含义是图算法。适合代表动态规划/图算法中的矩阵式更新。

24. `medley/nussinov/nussinov.c`

   `nussinov` 是 Nussinov RNA 二级结构预测算法。它通过动态规划估计 RNA 序列中碱基配对结构。

   默认 LARGE 规模是 `N=2500`，可以理解为 RNA 序列长度为 2500。输入是序列，输出是动态规划表。

   时间复杂度约为 `O(N^3)`。动态规划表有 `O(N^2)` 个区间状态，而部分状态需要遍历一个分割点或配对位置，因此总体达到三次方级别。

   它的循环结构和普通矩阵算法不同，通常沿动态规划表的斜线或区间长度推进。适合代表生物信息学中的动态规划任务，控制流和数据依赖都比较有特点。

## 6. stencils：模板/网格迭代类程序

Stencil 程序通常在一维、二维或三维网格上反复迭代，每个网格点的新值由邻域点计算得到。这类程序很常见于 PDE 求解、热传导、流体、电磁仿真等科学计算。它们通常内存带宽敏感，且时间步 `TSTEPS` 或 `TMAX` 是非常关键的输入规模。

25. `stencils/adi/adi.c`

   `adi` 是 Alternating Direction Implicit 方法，用于数值求解偏微分方程。它在两个方向上交替进行隐式更新。

   默认 LARGE 规模是 `TSTEPS=500, N=1000`。输入是 `N x N` 网格，程序执行 500 个时间步，输出是最终网格状态。

   时间复杂度约为 `O(TSTEPS * N^2)`。每个时间步会对二维网格执行若干次方向性扫描，扫描次数是常数级。

   它有明显的时间步循环和二维网格循环，并且每一步有方向性依赖。适合代表 PDE 求解类任务。

26. `stencils/fdtd-2d/fdtd-2d.c`

   `fdtd-2d` 是二维 Finite-Difference Time-Domain 方法，常用于电磁场传播仿真。

   默认 LARGE 规模是 `TMAX=500, NX=1000, NY=1200`。输入是二维场数组，程序执行 500 个时间步，输出是更新后的电场/磁场相关数组。

   时间复杂度约为 `O(TMAX * NX * NY)`。每个时间步需要扫描二维网格上的多个场变量，但变量数量是常数级。

   它是非常典型的二维 stencil：每个时间步扫描网格并更新相邻场变量。适合观察 load/store 密度、数组邻域访问和时间步对运行时间的影响。

27. `stencils/heat-3d/heat-3d.c`

   `heat-3d` 是三维热扩散模拟。它用三维网格上的邻域值来更新每个点的温度。

   默认 LARGE 规模是 `TSTEPS=500, N=120`。这里 `N=120` 是三维网格每个维度的大小，整体网格规模约为 `120 x 120 x 120`，再乘以 500 个时间步。

   时间复杂度约为 `O(TSTEPS * N^3)`。每个时间步需要遍历三维网格中的内部点，并读取固定数量的邻域点。

   虽然单个维度看起来比二维 stencil 小，但三维数组总体数据量和访存压力很高。它适合代表 3D stencil 和 cache 压力大的科学计算任务。

28. `stencils/jacobi-1d/jacobi-1d.c`

   `jacobi-1d` 是一维 Jacobi 迭代。每个点的新值由相邻点计算得到。

   默认 LARGE 规模是 `TSTEPS=500, N=2000`。输入是一维数组，程序迭代 500 次，输出是最终数组。

   时间复杂度约为 `O(TSTEPS * N)`。每个时间步只需要线性扫描一维数组。

   它结构简单，适合用作 stencil 类的入门样本。由于循环规整，模型应该能比较容易从 AST/CFG/IR 中识别出时间步循环和数组访问模式。

29. `stencils/jacobi-2d/jacobi-2d.c`

   `jacobi-2d` 是二维 Jacobi 迭代。每个网格点的新值由上下左右邻域点计算得到。

   默认 LARGE 规模是 `TSTEPS=500, N=1300`。输入是 `N x N` 网格，输出是迭代后的二维数组。

   时间复杂度约为 `O(TSTEPS * N^2)`。每个时间步需要扫描二维网格上的内部点，邻域大小是常数。

   与 `jacobi-1d` 相比，它的数据规模和邻域访问都更复杂。它适合观察二维 stencil 的内存带宽需求和 cache 局部性。

30. `stencils/seidel-2d/seidel-2d.c`

   `seidel-2d` 是二维 Gauss-Seidel 风格迭代。它和 Jacobi 类似，也在二维网格上迭代，但更新方式通常会使用本轮已经更新过的邻近点。

   默认 LARGE 规模是 `TSTEPS=500, N=2000`。输入是 `N x N` 网格，输出是最终二维数组。

   时间复杂度约为 `O(TSTEPS * N^2)`。它与 Jacobi-2D 的阶数相同，但由于原地更新和数据依赖不同，实际运行表现可能不同。

   它与 `jacobi-2d` 的重要区别是数据依赖更强，因为 Seidel 更新不是完全基于上一轮数组。它适合研究相似 stencil 结构下，不同数据依赖对运行时间的影响。

## 7. 对本项目实验的理解方式

1. PolyBenchC 适合作为第一阶段正式实验数据集，因为它的源代码相对规整、输入规模明确、程序数量适中，且每个程序都有清晰的计算语义。

2. 每个 benchmark 应该以 `xxx.c + xxx.h + utilities/polybench.c/h` 为一个整体来看，而不是只看单个 `.c` 文件。`.h` 中的宏定义就是输入规模的重要来源。

3. 做运行时间预测时，建议至少记录这些规模字段：矩阵维度、网格维度、时间步数、数据类型、编译优化等级、运行环境。

4. 时间复杂度可以作为输入规模特征设计的依据。例如，`gemm` 应重点记录 `NI,NJ,NK`，`jacobi-2d` 应重点记录 `TSTEPS,N`，`fdtd-2d` 应重点记录 `TMAX,NX,NY`。如果只记录一个泛化的 `N`，会丢失大量解释运行时间的关键信息。

5. 对模型来说，PolyBenchC 可以帮助验证几个关键关系：循环深度与运行时间、load/store 与内存压力、浮点算术指令与计算密集度、CFG 分支/回边与控制流复杂度、输入规模复杂度项与运行时间增长趋势。

6. 如果后续要扩展到 Rodinia，PolyBenchC 可以作为“规则、干净、单程序结构”的基线；Rodinia 则是“真实、多文件、多输入、多并行模型”的进阶数据集。
