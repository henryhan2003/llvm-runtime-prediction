# 项目运行流程说明

## 1. 项目目标

本项目为执行时间预测实验采集三类数据：

1. PolyBenchC 串行 CPU 程序。
2. Rodinia OpenMP 多线程 CPU 程序。
3. Rodinia CUDA GPU 程序。

每条流水线负责生成程序表示、提取静态指标、编译运行 benchmark、重复测量运行时间，并按配置写出 CSV 和环境清单。

```text
source code + input configuration + environment
  -> Clang AST / LLVM IR / CFG
  -> static feature extraction
  -> build executable
  -> warmup + repeated measurement window
  -> process / Prometheus / GPU telemetry
  -> timestamped experiment results
```

## 2. 当前三条正式流水线

| 数据集 | 正式入口 | 配置来源 | 执行设备 |
|---|---|---|---|
| PolyBenchC | `scripts/pipeline_new.py` | 同名 `.h` 中的五种数据规模 | CPU 串行 |
| Rodinia OpenMP | `scripts/pipeline_rodinia.py` | `configs/rodinia_openmp.json` | CPU 多线程 |
| Rodinia CUDA | `scripts/pipeline_rodinia_cuda.py` | `configs/rodinia_cuda.json` | NVIDIA GPU |

`scripts/generate_ast.py`、`scripts/generate_ir.py` 和 `scripts/generate_cfg.py` 是静态采集兼容入口，统一调用 `pipeline_new.py --no-run`。运行任意一个都会一次生成 AST、LLVM IR、CFG 和静态指标，并不是三套不同的实现。

## 3. 共用静态指标核心

三条正式流水线共用 `pipeline_new.py` 中的以下函数：

- `generate_ast()`：调用 Clang AST dump。
- `generate_ir()`：调用 Clang 生成文本 LLVM IR。
- `generate_cfg()`：优先调用 `opt -passes=dot-cfg`，找不到 `opt` 时使用 Clang DumpCFG。
- `extract_ast_features()`、`extract_ir_features()`、`extract_cfg_features()`：使用同一套指标定义。

PolyBenchC 通常是单翻译单元，直接提取一行指标。Rodinia OpenMP 和 CUDA 经常包含多个源文件，因此先逐翻译单元提取，再按相同规则聚合为程序级指标：计数求和、深度取最大值、平均常量按数量加权。

语言相关编译参数必须不同：

- PolyBenchC 使用 `-D<PROFILE>` 选择输入规模。
- OpenMP 使用 `-fopenmp` 和 benchmark 自身 include 目录。
- CUDA 使用 CUDA 路径、GPU 架构和 CUDA 前端参数。

当前 CUDA 通用 LLVM 表示使用 `--cuda-host-only`，因此通用 IR/CFG 主要描述主机端逻辑，不等同于 GPU device kernel IR/CFG。CUDA 流水线另外提取 `cuda_*` 源码特征；后续如果预测 kernel-only 时间，还应增加独立的 `device_ir_*` 和 `device_cfg_*`。

## 4. 测量规则

三条流水线都支持以下测量参数：

| 参数 | 含义 |
|---|---|
| `--warmup N` | 正式计时前的预热次数 |
| `--measurement-seconds S` | 每个配置的正式测量时间预算 |
| `--min-measured-runs N` | 即使达到时间预算也至少执行的次数 |
| `--runs N` | 仅当 `--measurement-seconds 0` 时使用的固定测量次数 |
| `--timeout S` | 单次 benchmark 的超时上限 |

正式采集以 `--measurement-seconds 10` 为主：在约 10 秒的窗口内重复运行当前配置，然后以各次运行时间的中位数作为主要标签。原始重复记录用于估计噪声，不应当作相互独立的程序样本。

## 5. PolyBenchC

### 5.1 全部五种规模

不指定 `--polybench-profile` 时，默认依次采集：

`MINI_DATASET`、`SMALL_DATASET`、`MEDIUM_DATASET`、`LARGE_DATASET`、`EXTRALARGE_DATASET`。

```powershell
python scripts/pipeline_new.py `
  --source-dir datasets/PolyBenchC-4.2.1 `
  --dataset PolyBenchC-4.2.1 `
  --task-type numerical_benchmark `
  --parallel-model serial `
  --warmup 5 `
  --measurement-seconds 10 `
  --min-measured-runs 3 `
  --timeout 300
```

### 5.2 只采一个规模

```powershell
python scripts/pipeline_new.py `
  --source-dir datasets/PolyBenchC-4.2.1 `
  --dataset PolyBenchC-4.2.1 `
  --polybench-profile MINI_DATASET `
  --warmup 5 `
  --measurement-seconds 10 `
  --timeout 300
```

### 5.3 只生成静态表示

```powershell
python scripts/pipeline_new.py `
  --source-dir datasets/PolyBenchC-4.2.1 `
  --dataset PolyBenchC-4.2.1 `
  --no-run
```

## 6. Rodinia OpenMP

OpenMP 流水线由 `configs/rodinia_openmp.json` 描述每个 benchmark 的源文件、编译命令、运行参数、输入文件和线程数。静态指标默认开启。

先查看清单或检查命令：

```powershell
python scripts/pipeline_rodinia.py --list
python scripts/pipeline_rodinia.py --all --input-profile official --dry-run
```

正式采集：

```powershell
$Stamp = Get-Date -Format "yyyyMMdd_HHmmss"
python scripts/pipeline_rodinia.py `
  --all `
  --input-profile official `
  --warmup 5 `
  --measurement-seconds 10 `
  --min-measured-runs 3 `
  --timeout 300 `
  --clean `
  --results-dir "results/rodinia_openmp_full_$Stamp"
```

只运行一个 benchmark 时使用 `--benchmark bfs`；可以重复该参数，或传入逗号分隔的多个名称。

## 7. Rodinia CUDA

CUDA 流水线由 `configs/rodinia_cuda.json` 描述 benchmark。运行前必须能找到 `nvcc` 和 `nvidia-smi`，并通过 GPU 架构和空闲状态检查。

先检查清单和命令：

```powershell
python scripts/pipeline_rodinia_cuda.py --list
python scripts/pipeline_rodinia_cuda.py --all --input-profile official --dry-run
```

正式采集：

```powershell
$Stamp = Get-Date -Format "yyyyMMdd_HHmmss"
python scripts/pipeline_rodinia_cuda.py `
  --all `
  --input-profile official `
  --warmup 5 `
  --measurement-seconds 10 `
  --min-measured-runs 3 `
  --timeout 300 `
  --clean `
  --collect-static `
  --cuda-arch auto `
  --gpu-index 0 `
  --gpu-metrics nvidia-smi `
  --results-dir "results/rodinia_cuda_full_$Stamp"
```

CUDA 默认只采集 CUDA 源码指标，不生成通用 AST/IR/CFG；正式命令需要显式加入 `--collect-static`。正式实验不要使用 `--allow-busy-gpu`，否则同一块 GPU 上的其他进程会污染运行时间和设备遥测。

## 8. Prometheus 和运行时指标

Windows 上 `--prometheus-exporter auto` 选择 Windows Exporter，Linux 上选择 Node Exporter。也可以显式指定：

```text
--prometheus-exporter windows --prometheus-job windows --prometheus-instance 127.0.0.1:9182
--prometheus-exporter node --prometheus-job node --prometheus-instance 127.0.0.1:9100
```

每个配置采用 before、during、after 三阶段采样，并记录背景校正后的主机 CPU、内存、磁盘和网络指标。Linux 运行还使用进程探针记录 CPU 时间、峰值 RSS、缺页和 I/O。CUDA 流水线额外通过 `nvidia-smi` 采集 GPU 利用率、显存、功耗、温度和时钟。

这些运行后指标用于资源分析、异常检测或辅助标签。若研究目标是“程序运行前预测执行时间”，不能把 during/after、进程资源和实际 GPU 利用率作为模型输入，以免产生 target leakage。

## 9. 输出文件

### 9.1 PolyBenchC

`pipeline_new.py` 当前写入项目 `results/`：

| 文件 | 内容 |
|---|---|
| `program_static_features.csv` | 每个程序和输入规模的静态指标 |
| `run_records.csv` | 每次 warmup/measure 的原始记录 |
| `run_summary.csv` | 每个程序和输入规模的测量汇总 |
| `results_<时间戳>.csv` | 静态指标、环境和运行汇总宽表 |
| `environment_manifest.json` | 环境、工具链和采集参数 |

其中宽表每次使用新时间戳；前三个 CSV 和环境清单使用固定文件名，下一次运行会覆盖。需要保留整次实验时，应在运行后把这些文件放入独立的时间戳目录。

### 9.2 Rodinia OpenMP

指定的 `--results-dir` 中生成：

- `rodinia_openmp_summary_<时间戳>.csv`
- `rodinia_openmp_runs_<时间戳>.csv`
- `rodinia_openmp_environment_<时间戳>.json`

### 9.3 Rodinia CUDA

指定的 `--results-dir` 中生成：

- `rodinia_cuda_summary_<时间戳>.csv`
- `rodinia_cuda_runs_<时间戳>.csv`
- `rodinia_cuda_environment_<时间戳>.json`

三类静态表示分别写入 `ast/`、`llvm_ir/`、`cfg/`；Rodinia 使用 `rodinia_openmp/` 和 `rodinia_cuda/` 子目录避免互相覆盖。

## 10. 建模时的使用边界

1. 主要运行时间标签使用 `runtime_sec_median`，保留均值、标准差和 CV 用于质量控制。
2. 输入特征只使用运行前已知字段，例如 AST/IR/CFG、输入规模、优化级别、线程数和硬件静态信息。
3. 按 `program_id` 分组划分训练集与测试集，不能随机拆分同一程序的不同输入规模。
4. PolyBenchC、OpenMP、CUDA 必须保留 `parallel_model`，不要把不同执行模型当成同一种样本。
5. 相同机器上的三条流水线应使用相同 `env_id`；更换 CPU、GPU、编译器或关键系统配置后应创建新 `env_id`。
6. 表示编译器和运行编译器可能不同。当前常见组合是 Clang 生成表示，GCC/G++ 或 NVCC 生成实际可执行文件，建模和论文中必须明确记录。
