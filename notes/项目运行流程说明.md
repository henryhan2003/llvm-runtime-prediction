# 项目运行流程说明

## 1. 项目目标

本项目用于把 `datasets` 中的 C/C++ 源代码自动转换为三类程序表示：

1. Clang AST：输出到 `ast/`
2. LLVM IR：输出到 `llvm_ir/`
3. CFG：输出到 `cfg/`

随后，流水线会从这些表示中抽取静态指标，并可选地编译运行程序、采集运行时间，最终把静态特征和运行时间标签写入 `results/*.csv`。

整体流程是：

```text
source code
  -> clang AST / LLVM IR / CFG
  -> AST features + CFG features + LLVM IR features
  -> compile executable
  -> warmup + measured runs
  -> CSV dataset for runtime modeling
```

## 2. 主要文件

| 文件 | 作用 |
|---|---|
| `scripts/pipeline.py` | 主流水线脚本，负责表示生成、指标提取、运行计时和 CSV 输出 |
| `main.py` | 项目根目录入口，等价于调用 `scripts/pipeline.py` |
| `scripts/generate_ast.py` | 兼容旧入口；现在调用主流水线并加 `--no-run` |
| `scripts/generate_ir.py` | 兼容旧入口；现在调用主流水线并加 `--no-run` |
| `scripts/generate_ir_new.py` | 兼容旧入口；现在调用主流水线并加 `--no-run` |
| `scripts/generate_cfg.py` | 兼容旧入口；现在调用主流水线并加 `--no-run` |
| `scripts/search_time.py` | 兼容旧入口；现在调用主流水线，包含运行时间采集 |
| `scripts/compat_include/` | Windows 下为 PolyBenchC 提供少量 POSIX 兼容头，不修改原始 benchmark 源码 |
| `datasets/test/*.c` | 测试用 C 源码，覆盖循环、矩阵、分支、递归、动态内存等场景 |
| `results/results.csv` | 汇总表，包含静态指标和运行时间摘要 |

## 3. 快速测试命令

在项目根目录运行：

```powershell
python scripts\pipeline.py --source-dir datasets\test --dataset test --warmup 1 --runs 2 --timeout 10
```

或运行：

```powershell
python main.py --source-dir datasets\test --dataset test --warmup 1 --runs 2 --timeout 10
```

运行后应看到类似输出：

```text
[pipeline] processing test01.c
[pipeline] processing test02.c
...
[pipeline] processed 6 programs
[pipeline] wrote E:\Dareway\LLVM_v01\results\results.csv
```

## 4. 正式采集建议命令

按照实验规范，正式采集建议使用 5 次 warmup、30 次正式测量：

```powershell
python scripts\pipeline.py --source-dir datasets\test --dataset test --warmup 5 --runs 30 --timeout 60
```

如果只想生成 AST、LLVM IR、CFG 和静态指标，不运行程序：

```powershell
python scripts\pipeline.py --source-dir datasets\test --dataset test --no-run
```

如果要尝试 PolyBenchC：

```powershell
python scripts\pipeline.py --source-dir datasets\PolyBenchC-4.2.1 --dataset PolyBenchC --task-type polybench_kernel --warmup 1 --runs 3 --timeout 60 --exclude utilities/* --exclude */Nussinov.orig.c
```

正式跑 PolyBenchC 或 Rodinia 前，建议先用少量轮次验证编译和输入规模，再扩大到 `--warmup 5 --runs 30`。

如果只是验证 PolyBenchC 的表示生成和静态指标，不采集运行时间：

```powershell
python scripts\pipeline.py --source-dir datasets\PolyBenchC-4.2.1 --dataset PolyBenchC --task-type polybench_kernel --no-run --exclude utilities/* --exclude */Nussinov.orig.c
```

## 5. 工具链说明

当前流水线默认：

| 用途 | 默认工具 |
|---|---|
| AST 生成 | `clang` / `clang++` |
| LLVM IR 生成 | `clang` / `clang++` |
| 可执行文件编译 | `gcc` / `g++` |
| CFG 生成 | 优先 `opt -passes=dot-cfg`；如果找不到 `opt`，自动使用 Clang `debug.DumpCFG` 文本 CFG |

本机当前能找到 `clang` 和 `gcc`，但 `opt` 不在 PATH 中，所以默认会走 Clang CFG fallback。这个 fallback 仍然会生成 `cfg/*.cfg.txt` 并提取 CFG 指标。

在 Windows 上运行 PolyBenchC 时，流水线会通过 `scripts/compat_include/` 兼容 `unistd.h`、`sys/resource.h` 和 `posix_memalign`，并在构建 benchmark 可执行文件时自动链接 `utilities/polybench.c`。

如需指定工具：

```powershell
python scripts\pipeline.py --c-compiler clang --cxx-compiler clang++ --run-c-compiler gcc --run-cxx-compiler g++
```

## 6. 输出目录与文件

| 输出 | 内容 |
|---|---|
| `ast/<program>.ast` | Clang AST 文本 |
| `llvm_ir/<program>.ll` | LLVM IR 文本 |
| `cfg/<program>.cfg.txt` | Clang DumpCFG 文本 fallback |
| `cfg/<program>/*.dot` | 如果安装了 `opt`，会生成 dot CFG |
| `build/pipeline/<program>.exe` | 编译后的测试可执行文件 |
| `results/program_static_features.csv` | 每个程序一行，包含 AST/CFG/LLVM IR 静态指标 |
| `results/run_records.csv` | 每次 warmup/measure 的原始运行记录 |
| `results/run_summary.csv` | 每个程序的运行时间汇总 |
| `results/results.csv` | 静态指标 + 运行时间汇总的合并表 |
| `results/environment_manifest.json` | 本次采集环境和工具链版本 |

如果 CSV 正被 Excel、WPS 或编辑器占用，流水线不会中断，而是自动写成带时间戳的备用文件，例如 `results_20260623_143000.csv`。

## 7. CSV 表之间的关系

| 表 | 粒度 | 主键/关联字段 |
|---|---|---|
| `program_static_features.csv` | 一个程序一行 | `program_id`, `compile_config_id` |
| `run_records.csv` | 每次运行一行 | `run_id`, `program_id`, `env_id`, `input_id` |
| `run_summary.csv` | 一个程序在一个环境和输入下一行 | `program_id`, `env_id`, `input_id`, `compile_config_id` |
| `results.csv` | 建模用宽表 | `program_id` |

第一版建模可以直接读取 `results/results.csv`。如果后续要做多输入规模、多环境、多线程实验，建议改用前三张表按 `program_id + input_id + env_id + compile_config_id` 连接。

## 8. 已实现的指标类型

### AST 指标

包含函数数量、调用数量、递归标记、for/while/do 循环数量、最大循环深度、if/switch、二元运算、数组访问、指针解引用、动态内存调用、常量统计、OpenMP pragma、CUDA kernel 声明等。

### CFG 指标

包含 CFG 函数图数量、基本块数量、边数量、圈复杂度、分支块、合流块、平均入度/出度、最大出度、回边、自然循环近似、CFG 深度、critical edge 等。

### LLVM IR 指标

包含 IR 指令数、load/store、memory 指令、GEP、alloca、memcpy/memset、call、外部调用、branch、switch、phi、select、icmp/fcmp、整数/浮点算术、向量操作、原子操作、同步调用、常量统计，以及 `load_store_ratio`、`memory_arithmetic_ratio`、`branch_instruction_ratio` 等派生指标。

### 输入规模指标

当前实现会从源码中的 `#define` 和整数字面量中做轻量推断，输出 `input_size_n`、`matrix_m`、`matrix_n`、`matrix_k`、`graph_nodes`、`graph_edges`、`image_width`、`image_height`、`iterations` 等字段。后续如果要严谨支持 Rodinia/PolyBench 多输入规模，应增加独立的 `input_manifest.csv`。

## 9. test 示例说明

| 文件 | 覆盖场景 |
|---|---|
| `test01.c` | 简单 for 循环 |
| `test02.c` | 简单 for 循环，循环边界不同 |
| `test03.c` | 简单 for 循环，循环边界更小 |
| `test04_matrix.c` | 矩阵初始化、三重循环、数组访存、乘加计算 |
| `test05_branch_search.c` | 分支密集查找、if/else、数组访问 |
| `test06_recursive_alloc.c` | 递归调用、malloc/free、数组写入 |

这些示例用于检查指标是否有区分度。例如 `test04_matrix.c` 的循环数量、最大循环深度、数组访问、load/store 通常会高于简单循环；`test06_recursive_alloc.c` 会出现递归标记和动态内存调用。

## 10. 注意事项

1. 当前流水线主要支持 `.c/.cc/.cpp/.cxx`。CUDA `.cu` 文件后续应单独增加 `nvcc` 或 clang CUDA 参数。
2. 如果程序需要命令行参数或输入文件，应先在后续版本中增加 `input_manifest.csv`，不要把不同输入混在同一行。
3. 如果程序非 0 退出，流水线会认为运行失败；测试程序应 `return 0`。
4. 如果安装了 LLVM `opt` 并加入 PATH，CFG 会优先生成 `.dot`；否则使用 `.cfg.txt` fallback。
5. 正式实验建议使用 `--warmup 5 --runs 30`，测试阶段可以使用较小轮次。
